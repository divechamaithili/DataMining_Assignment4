# DataMining_Assignment4
Three Methodologies, Three Data-Science Projects
This repository is a complete portfolio assignment demonstrating three established data-mining methodologies on three different datasets:
Methodology	Project	Dataset	Main question
CRISP-DM	Telco customer churn	Kaggle IBM Telco Customer Churn	Which customers are most likely to churn, and how should retention resources be prioritized?
SEMMA	Student performance	Kaggle copy of UCI Student Performance	Can final grades be predicted, and can students needing early academic support be identified?
KDD	Online retail bundles	Kaggle E-Commerce Data / UCI Online Retail	Which products are frequently purchased together and could form useful bundles?


The work is organized as three separate projects. Each project contains a phase-by-phase report, a Google Colab-compatible notebook, executable Python code, generated artifacts, tests, a Medium-ready article, and a record of AI-assisted critique and revisions.

Project 1: CRISP-DM — Telco Customer Churn
Directory: [`projects/crisp_dm/`](projects/crisp_dm/)
https://youtu.be/rFc17rCt0UE
Notebook: [`crisp_dm_telco_churn.ipynb`](projects/crisp_dm/notebooks/crisp_dm_telco_churn.ipynb)

Dataset: Kaggle IBM Telco Customer Churn
CRISP-DM phases demonstrated
1. Business understanding — define churn-risk prioritization as the business problem, identify the cost of missed churners versus unnecessary outreach, and define success measures.
2. Data understanding — inspect shape, schema, target balance, missing values, data types, descriptive statistics, and churn patterns.
3. Data preparation — normalize TotalCharges, remove unusable records, separate the target, encode categorical variables, and build a leakage-safe preprocessing pipeline.
4. Modeling — compare a baseline, balanced logistic regression, and balanced random forest.
5. Evaluation — use ROC-AUC, precision, recall, confusion matrices, classification reports, and threshold analysis rather than relying only on accuracy.
6. Deployment — save the model, metrics, and feature metadata; expose a small Streamlit prediction interface.
The report also discusses class imbalance, probability thresholds, false-positive costs, and why a model score should support human retention decisions rather than automatically penalize customers.
Project 2: SEMMA — Student Performance
Directory: [`projects/semma/`](projects/semma/)
https://youtu.be/2GyCpchXIuM
Notebook: [`semma_student_performance.ipynb`](projects/semma/notebooks/semma_student_performance.ipynb)

Dataset: Kaggle Student Performance Data Set, with additional provenance from the UCI Student Performance dataset
SEMMA stages demonstrated
1. Sample — load the mathematics subject data and create reproducible train/test samples.
2. Explore — inspect distributions, missingness, duplicates, correlations, grade distributions, absences, study time, and demographic variables.
3. Modify — encode categorical fields, impute where required, scale numeric features when appropriate, and create the at_risk target where G3 < 10.
4. Model — train a final-grade regression model and an early-warning classification model using linear/logistic and tree-based approaches.
5. Assess — compare RMSE, R², ROC-AUC, precision, recall, confusion matrices, and the practical implications of false negatives.
An important modeling decision is documented explicitly: G1 and G2 are previous grades and are highly predictive of G3. They are appropriate for end-of-term grade prediction, but they are excluded from the early-warning model so that the intervention scenario does not use information that would arrive too late.

The optional SAS-style mapping is in [`semma_mapping.sas`](projects/semma/sas/semma_mapping.sas). It maps the Python workflow to Sample, Explore, Modify, Model, and Assess tasks; it is not a claim that SAS Enterprise Miner was executed in this environment.
Project 3: KDD — Online Retail Association Rules
Directory: [`projects/kdd/`](projects/kdd/)
https://youtu.be/EyltWd_CJog
Notebook: [`kdd_online_retail.ipynb`](projects/kdd/notebooks/kdd_online_retail.ipynb)

Dataset: Kaggle E-Commerce Data, with additional provenance from UCI Online Retail
KDD stages demonstrated
1. Selection — select transaction, product, quantity, price, date, customer, and country fields; use the UK scope for a focused basket analysis.
2. Preprocessing — remove duplicate rows, cancellations, missing descriptions, non-positive quantities, and invalid prices.
3. Transformation — aggregate invoice-product quantities and convert transactions into a one-hot basket matrix.
4. Data mining — run Apriori with minimum support 0.03 and generate association rules with minimum confidence 0.35.
5. Interpretation/evaluation — rank rules by lift, while also checking support and confidence so that rare but impressive-looking rules are not over-interpreted.
6. Knowledge consolidation — turn the strongest rules into bundle, cross-sell, and merchandising recommendations, with an experiment plan for validating them in production.
The analysis identifies the classic association-rule distinction between correlation and causation: a high-lift rule is a merchandising hypothesis, not proof that placing two products together will cause incremental sales.

Important limitations and responsible use
- These datasets are educational/public benchmark datasets and should not be treated as evidence about any specific real customer or student.
- Churn predictions can create unfair targeting if they are used without monitoring and human oversight.
- Student predictions should support resources and advising, never determine a student’s worth or access to education.
- Association rules describe co-occurrence, not causation or guaranteed incremental revenue.
- Reported scores depend on the supplied dataset, preprocessing choices, random seeds, and threshold decisions.
- Raw uploaded datasets are intentionally not required in Git history. Download them from the cited sources or upload them to Colab locally.
